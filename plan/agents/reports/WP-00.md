## Implementation and boundaries

The isolated [prototype](../../../feasibility/wp00/README.md) is a finite experiment,
not the service foundation. Four modules provide reusable boundary examples:

- `storage`: one dedicated thread and SQLite connection, 128-command Tokio
  channel with immediate rejection on saturation, asynchronous startup/result
  acknowledgements, parameterized SQL, explicit commit and rollback, clean
  checkpoint/close and reopen. FULL synchronous WAL, foreign keys, 2 MiB page
  cache target and two-second busy timeout. Main page ceiling is derived from
  actual page size for 512 MiB. The tiny sample table is not the application schema.
- `hashing`: Argon2id v1.3, 19 MiB, two iterations, one lane, 32-byte output.
  A one-permit `try_acquire_owned` rejects excess work without a waiting queue.
  The permit lives inside `spawn_blocking`, including after caller cancellation.
  Synthetic input and fixed test salt demonstrate cost only; production needs
  random salts, PHC storage/verification, input/rate limits and secret handling.
- `transport`: Axum static loopback fixture and local rustls TLS fixture;
  reqwest client with five-second deadline, redirects/retries/proxy inheritance
  disabled, HTTP/1 only, zero retained idle connections, and pinned localhost
  resolution. Trusted local certificate succeeds; untrusted certificate and
  hostname mismatch fail. Response bodies are dropped unread. TCP sends no payload.
- `ping`: native Windows synchronous `IcmpSendEcho` / `Icmp6SendEcho2` with RAII
  handles, aligned bounded reply storage and documented FFI safety invariants.
  Checks source, success status and echoed payload; native APIs supply request
  correlation. Linux source uses `SOCK_DGRAM` ICMP/ICMPv6 without a raw-socket
  fallback, kernel-assigned identifier, sequence/payload/source/type checks,
  deadline and at most eight received packets. Linux code is **not compiled or
  executed** here. The additional Linux reply-validation test is likewise unrun.

All destinations are fixed, explicitly permitted loopback fixtures. There is no
arbitrary target input, DNS discovery, private-network policy widening, exposed
monitor data, credential route or Telegram API call. The Axum fixture is not a
hardened production listener; full connection/header/body/request admission,
authentication and CSRF belong to their assigned packages. The program uses two
Tokio workers and at most four probe tasks, exercises 15 local HTTP/TCP/ping probes,
hashes twice sequentially, observes two three-second idle phases, and exits.
Its `wp00=passed` stdout marker means that this finite harness passed, not that
the package completion gate or release acceptance passed.

Final fmt, clippy and diff whitespace checks passed. Final Windows tests: **9
passed, 0 failed, 0 ignored**, 2.04 seconds. They cover hashing admission/release,
SQLite commit/rollback, channel saturation, Windows IPv4/IPv6 ping, fixture policy
denial, TLS trust/hostname validation, HTTP/TCP success, TCP refusal, response
deadline, and the oversized-header characterization. Release harness exited 0
and additionally checked persisted data after database close/reopen.

The header characterization test passes by reproducing a **failed constraint**:
reqwest accepted a single 33 KiB HTTP/1 header value. This does not satisfy V-05
or V-06's required 32 KiB parsing limit. The selected public HTTP/1 client builder
does not expose that limit. A post-response header-map check alone cannot bound
the allocation already made while parsing.

Initial sandbox Cargo fetch failed with Schannel `SEC_E_NO_CREDENTIALS`;
rerunning the same dependency download outside the sandbox succeeded. Initial
WSL listing also failed with `E_ACCESSDENIED`; outside-sandbox read-only calls
succeeded. No TLS verification was disabled. A clippy `unused_io_amount` finding
in the fixture test was corrected and rechecked. An initial inline WSL diagnostic
had a shell quoting error; the saved Python script avoids it. An initial Windows
measurement wrapper changed its caller's working directory, breaking subsequent
relative-path inspection; that side effect was removed. No unresolved Windows
build/test/lint failure remains.

Linux diagnostic: existing `ping_group_range = 1 0`; **both IPv4 and IPv6 datagram
socket creation return errno 13, Permission denied** as UID 1002. This is real
Linux permission-fault evidence using Python, not Rust adapter or successful echo
evidence. No Rust/Linux build, test, TLS, release, signal, service or DNS test was
run. No tooling was installed or ping permissions changed.

## Dependencies and platform choices

Locked direct versions on Windows: Axum 0.8.9, Tokio 1.53.2, reqwest 0.12.28,
rusqlite 0.37.0, Argon2 0.5.3, windows-sys 0.61.2. Bundled SQLite runtime reports
**3.50.2**. rustls resolves to 0.23.45 with ring; fixture-only rcgen 0.14.10 and
tokio-rustls 0.26.6 add local certificate/server support. Linux-only socket2 locks
to 0.6.5. No Node runtime, external database, container daemon, shell-based ping,
raw-socket fallback or platform TLS dependency was introduced. Dependency
advisory/license auditing is unperformed and remains a foundation/release task.

Production must ship only the Linux binary/assets and controlled configuration,
state/log/backup allocations. It needs no C compiler, Rust or SQLite server at
runtime. Windows native ICMP uses the OS DLL. Linux requires the reviewed service
group's narrow datagram permission; missing permission remains a local health
fault, never a target-down incident. Trust roots here are webpki roots plus a
single in-memory test certificate; Linux/private-CA behavior remains to be tested.

API references consulted: [Microsoft IPv4 echo](https://learn.microsoft.com/en-us/windows/win32/api/icmpapi/nf-icmpapi-icmpsendecho2),
[Microsoft IPv6 echo and reply-buffer requirements](https://learn.microsoft.com/en-us/windows/win32/api/icmpapi/nf-icmpapi-icmp6sendecho2),
[Linux ping group controls](https://docs.kernel.org/networking/ip-sysctl.html).
The IPv6 wrapper uses synchronous operation and the documented reply structure
followed by the echoed message body; it avoids callbacks retaining Rust buffers.
