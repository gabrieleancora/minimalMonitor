## Implementation decisions

D-25 records the additive preview field. At most 50 current monitors × 12 raw
observations are read and serialized, chronological within each monitor; the
existing 256 KiB response ceiling remains enforced. Individual heartbeats never
invent successful samples. A maximum-input test uses 50 monitors, 100 four-byte
characters per name, 2048-byte targets, 32 HTTP status ranges and 12 returned
observations each. It checks the response cap and oldest/newest preview timestamps.

The existing history API returns aggregated buckets, so the GUI labels those
explicitly; recent bars are separately labelled individual observations. Missing
buckets are hatched, never joined as green data. Clicking/keyboard activation
shows a visible timestamp/value; a table supplies the chart alternative.

Detail incident pagination uses the agreed global cursor API, with explicit
wording when the current global page has no matching incidents. No receipt on
the retained page means unconfirmed delivery. Historical probe categories are
not persisted in the incident contract; closure reasons and a generic target
failure description are shown without inventing historical transport details.

Theme startup is a synchronous local asset before CSS, compatible with existing
CSP. Storage denial is caught; the current page can still change theme. Polling
pauses when hidden, uses 15-second intervals plus <=750 ms jitter and 60-second
failure backoff, stops on authentication failure, and retains data with a prominent
stale refresh timestamp on network/storage errors. Settings inputs are not
replaced by polls. Create keys remain stable for retries of unchanged input;
mutations have no automatic retry. Password-change 401 checks session validity so
an incorrect current password does not falsely expire a valid session.
